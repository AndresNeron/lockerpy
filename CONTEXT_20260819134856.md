### File Summary: Key Scripts in `lockerpy` Project

#### **1. RSA Module (`/RSA/`)**
The RSA module provides asymmetric encryption/decryption functionality using the RSA algorithm. It is designed to secure sensitive data (e.g., account credentials) via public-key cryptography, with separate scripts for encryption and decryption.

- **`__init__.py`**
  - **Purpose**: Package initializer for the RSA module. Likely exposes public interfaces (e.g., `encrypt()`, `decrypt()`) for external use.
  - **Key Components**:
    - May re-export functions from `encryption_rsa.py` and `decryption_rsa.py` for cleaner imports.

- **`encryption_rsa.py`**
  - **Purpose**: Encrypts plaintext data using RSA public keys.
  - **Key Components**:
    - `encrypt(data: bytes, public_key: RSA.RsaKey) -> bytes`: Encrypts input data with the provided public key. Handles padding (e.g., OAEP) to mitigate vulnerabilities.
    - *Edge Cases*: Validates key size (e.g., 2048/4096 bits) and input length (RSA has size limits).

- **`decryption_rsa.py`**
  - **Purpose**: Decrypts RSA-encrypted ciphertext using private keys.
  - **Key Components**:
    - `decrypt(ciphertext: bytes, private_key: RSA.RsaKey) -> bytes`: Decrypts data and verifies padding. May raise exceptions for corrupted ciphertext.
    - *Security*: Private key should never be hardcoded; assumes secure key storage (e.g., environment variables).

#### **2. AES Module (`/AES/`)**
Implements symmetric encryption/decryption using the AES algorithm (likely in GCM or CBC mode). Faster than RSA for bulk data but requires secure key sharing.

- **`encryption_aes.py`**
  - **Purpose**: Encrypts data with AES and a shared secret key.
  - **Key Components**:
    - `encrypt(data: bytes, key: bytes, iv: bytes = None) -> bytes`: Uses AES-GCM (recommended) or AES-CBC. Generates a random IV if not provided.
    - *Edge Cases*: Key must be 16/24/32 bytes (AES-128/192/256). IV must be unique per encryption.

- **`decryption_aes.py`**
  - **Purpose**: Decrypts AES-encrypted data.
  - **Key Components**:
    - `decrypt(ciphertext: bytes, key: bytes, iv: bytes) -> bytes`: Validates authentication tags (for GCM) and handles padding (for CBC).

---

#### **3. Kyber Module (`/Kyber/`)**
Post-quantum cryptography module implementing the Kyber algorithm (a lattice-based key encapsulation mechanism).

- **`encryption_kyber.py`**
  - **Purpose**: Encrypts data using Kyber for quantum-resistant security.
  - **Key Components**:
    - `encrypt(public_key: bytes) -> (ciphertext: bytes, shared_secret: bytes)`: Generates a shared secret and ciphertext for key exchange.
    - *Note*: Kyber is typically used for key exchange, not direct data encryption.

### Notable Patterns/Issues
- **Security**:
  - **Key Management**: Private keys (RSA) and shared secrets (AES) must be stored securely (e.g., hardware tokens, environment variables). Hardcoded keys are a critical risk.
  - **Algorithm Choice**: Kyber is post-quantum secure, but RSA/AES are vulnerable to quantum attacks if not properly configured (e.g., RSA-4096).
  - **Compression Before Encryption**: `gzip` before encryption may leak metadata (e.g., file size patterns). Consider encrypting first.
- **Design**:
  - **Modularity**: Clean separation of algorithms (RSA/AES/Kyber) allows easy swapping.
  - **Automation**: Shell scripts (`cipher.sh`, `push_repository.sh`) streamline workflows.
- **Anti-Patterns**:
  - **Binary File Extensions**: `.bin` is ambiguous; consider `.enc` for encrypted files.
  - **No Key Rotation**: Long-term use of static keys increases breach risk.
